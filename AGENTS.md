# Работа с MultiTracker

## Область текущего этапа

Это статический кликабельный макет на вымышленных данных. Семь разделов —
Обзор, Портфели, Операции, Импорт, Подключения, Синхронизация, Настройки —
и их диалоги служат проверке интерфейса. Сохранение показывает демонстрационный
результат; настоящие API, файлы, ключи, база и шифрование отсутствуют.
Граница и текущая приёмка определены в
[плане полного макета](docs/plans/2026-09-30-complete-prototype.md) с
[R01–R21](openspec/changes/complete-prototype/specs/readiness/spec.md).
Расширение Delta ([D01–D07](openspec/changes/delta-capabilities/specs/exploration/spec.md),
[карта каталога](docs/design/delta-capabilities.md)) — историческое:
разделы «Рынки», «Избранное», «Аналитика» и «События» владелец убрал из
текущего объёма; полная версия сохранена тегом `prototype-full-11-sections`.
Монохром и предпросмотр виджета портфеля находятся в настройках. Услуги eToro,
виджеты ОС, аудио и настоящие внешние службы исключены.
План первого этапа сохранён как историческая запись; он не сокращает текущие
требования. Одобрение макета получено 2026-10-02 (PR №3 слит); настоящая реализация
начинается по отдельному решению владельца.
Будущий продукт описан отдельно в [дорожной карте](docs/plans/2026-09-30-roadmap.md).

## Простая структура и качество

- Перед изменением интерфейса прочитайте [DESIGN.md](DESIGN.md) целиком:
  это источник цветов, типографики, отступов и состояний компонентов.
  Обновляйте его вместе с изменением оформления. Для проверки документа
  доступен `.agents/skills/design-md-validator/SKILL.md`; валидатор документа
  не заменяет проверку экранов, клавиатуры и фактического поведения.

- Интерфейс живёт в `src/`, чистая учебная арифметика — в `src/model/`,
  проверки поведения — в `tests/`, проверки инструментов — в `scripts/`.
  Не создавайте пустые слои, сервер, контейнеры и инфраструктуру заранее.
- Новый код — TypeScript. `strict`, `noUncheckedIndexedAccess` и
  `exactOptionalPropertyTypes` обязательны.
- Файл до 300 строк, функция до 50 строк, обычная и когнитивная сложность до 10;
  считаются пустые строки, комментарии и JSX. Запрещены `let`, изменения объектов
  и массивов на месте, отключение правил и HTML-вставки. Длинные строки не заменяют
  содержательную организацию модулей.
- Перед завершением выполните `npm run check` и сохраните точные результаты.
  Prettier проверяет читаемую многострочную запись с шириной 100; форматирование
  не разрешает превышать лимиты длины функций и файлов.
  Заблокированная или незапущенная проверка не пройдена. Визуальную проверку
  ведите через отдельную именованную сессию agent-browser, проверяйте 375 и 1440 px,
  клавиатуру, подписи, контраст и фактическое действие управления в RU/EN.
  Проверки трёх UI-линз сводите в один итог; состязательная проверка находок
  входит в единственное финальное ревью. Прошедшие проверки кода не доказывают
  полноту продукта или удобство для людей разных возрастов.
  `npm run test:ui` — отдельная проверка agent-browser при запущенном сервере;
  она не заменяет полную матрицу сценариев и независимые UI-линзы.
- При обзоре проверяйте также назначение каталогов, осиротевшие файлы,
  строковые ссылки на пути и актуальность документации.
- Комплексный аудит по явному запросу ведите через `product-readiness`
  ([локальный пакет](skills/product-readiness/SKILL.md)); маршруты условны по цели
  и наличию навыков. Изолированная правка не запускает полный аудит.
- GitHub Actions и ручная публикация статического макета подготавливаются локально.
  Не выдавайте проверку конфигурации за удалённый запуск или публикацию.

## Совместная работа и знания

- Одновременно могут работать несколько сессий. Уточните владение файлами;
  не откатывайте чужие изменения. Установку npm выполняет один участник.
  Независимые исследования можно делегировать параллельно с чёткой областью.
- Проектный трекер — [GitHub Issues](https://github.com/apolenkov/multitracker/issues).
  Перед новой задачей ищите дубликаты; фиксируйте цель, решения, результат и следующие шаги.
  Требования находятся в репозитории, существенные решения — в `docs/decisions/`.
  Личный Backlog CLI владельца — необязательный частный инструмент; доступ к нему,
  локальным каталогам и карточкам `TASK-060.*` участникам не требуется.
  Подробнее: [источник задач](docs/agents/issue-tracker.md).
- Для делегирования предпочитайте Devin CLI с `--permission-mode dangerous`;
  при недоступности используйте нативных работников. Масштаб процесса соразмерен
  изменению: небольшому достаточно короткого плана; сложному — superpowers и OpenSpec.

## Безопасные данные

Не добавляйте настоящие выписки, ключи, пароли или сведения о пользователях.
Не отправляйте данные во внешние сервисы, не подключайте аналитику и удалённые шрифты.
Снимки сторонних интерфейсов — локальные доказательства с отдельными правами,
они исключены из Git. По безопасности следуйте [SECURITY.md](SECURITY.md).
Пишите пользователю по-русски и завершайте рабочий ответ проверенными строками
«Хвосты для агента» и «Хвосты для человека».
