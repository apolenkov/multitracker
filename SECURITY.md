# Безопасность

## Текущая область

MultiTracker — статический демонстрационный макет. Поддерживается текущая
версия основной ветки [репозитория](https://github.com/apolenkov/multitracker).
Не вводите настоящие портфели, выписки, пароли и ключи. Приложение не реализует
финансовый учёт для реальных денег, шифрование, обработку файлов, хранение
и подключение внешних сервисов.

Проверки исходников, зависимостей и секретов уменьшают известные риски;
они не заменяют модель угроз. До настоящих данных нужны отдельные решения
по расчётам, ключам, резервным копиям и восстановлению. Клиентский ключ не
защищает от вредоносной поставки JavaScript: код страницы может прочитать
доступные ей данные после разблокировки. [Резюме проверок](docs/reviews/prototype-readiness.md)
описывает границы текущего этапа.

## Сообщить об уязвимости

Откройте [Security Advisories](https://github.com/apolenkov/multitracker/security/advisories)
и выберите **Report a vulnerability** для закрытого сообщения владельцу.
Private vulnerability reporting включён; состояние подтверждено API GitHub
2026-09-30.
Не помещайте секреты, реальные данные и подробности эксплуатации в публичные
Issues, запросы на изменение или журналы.

Если кнопка недоступна, создайте [Issue](https://github.com/apolenkov/multitracker/issues)
с просьбой предоставить частный канал связи, **без описания уязвимости и
чувствительных данных**. Механизм описан в
[официальной инструкции GitHub](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).

В частном отчёте достаточно версии кода, шагов на вымышленных данных,
ожидаемого и наблюдаемого результата. Сроки ответа и программа вознаграждений
не объявлены. До устранения проблемы согласуйте раскрытие с владельцем.
