# Продолжение работы над MultiTracker

Публичный репозиторий — [apolenkov/multitracker](https://github.com/apolenkov/multitracker),
трекер — [GitHub Issues](https://github.com/apolenkov/multitracker/issues).
Текущий этап — расширенный статический макет из одиннадцати разделов: прежние
семь плюс рынки, избранное, аналитика и события. Настройки включают монохром
и предпросмотр виджетов. Услуги eToro, виджеты ОС, аудио и реальные внешние службы
исключены. Настоящие данные, финансовый движок,
файлы, API, база и шифрование не подключены. Пользователь разрешил публикацию
репозитория; одобрение полного макета для настоящей реализации ещё требуется.
Личные карточки `TASK-060.*` — история владельца, доступ к ним участникам не нужен.

## Историческая редакция арены: `3ced743`

[Приёмка](design/arena/acceptance.md) фиксирует `npm run check` прежнего кандидата
после исправлений:
32/32 теста и 39 проверок ограничений; Linux `test:ui` — 63/63 PASS при совпадении
146 входных файлов среза `3ced743`; строгая проверка OpenSpec — PASS. 162 кадра основного пакета
и 8 исторических показывают 44 сочетания раздела/ширины/темы, десять видов
операций, семь категорий настроек и представительские дополнительные состояния.
Настоящие 200% наблюдались только на обзоре и рынках. Полная матрица всех форм
на 320 px, английском и при увеличении не подтверждена.

Итоговое дополнение содержит восемь кадров обзора/покупки на 320 RU/EN в обеих
темах: scrollWidth=viewport=320, суммы легенды не обрезаны. Заполненное
редактирование → очистка с сохранением фокуса → явное сворачивание проверено.
Это восемь кадров, а не 24 при подсчёте PNG/DOM/snapshot отдельно.

Единственное независимое ревью прежнего кандидата завершено: F1–F3 закрыты, решение **ship**
в пределах проверенного статического макета, открытых существенных замечаний нет.
Проверяющий независимо сверил SHA-256 всех 146 входных файлов среза `3ced743`.
Удалённые проверки привязаны к коммиту; состояние каждого запуска сверяйте с его SHA в
[Checks черновика PR3](https://github.com/apolenkov/multitracker/pull/3/checks).
Ненулевая комиссия/заметка/ошибка удерживает раскрытие дополнительных сведений;
образцы импорта соответствуют фикстуре и скрывают числа при скрытии сумм.
Поведение воспроизводят `scripts/ui-operation-checks.ts` и
`scripts/ui-import-checks.ts`, `scripts/ui-overview-checks.ts`. Не объявляйте
общий PASS адаптивности по этим отдельным результатам.

Сырые журналы и снимки хранятся в исключённых из Git `docs/audits/` и
`docs/evidence/`; точные пути перечислены в приёмке. Старые доказательства
не заверяют текущий Mintlify; ранние доказательства семи разделов также
не заверяют D01–D07 и каталог. Арена использовала синий акцент действий,
отдельные финансовые цвета, четыре мобильных пункта и смысловые группы форм.
Текущие токены Mintlify — в [DESIGN.md](../DESIGN.md). Четыре отчёта по 135 ID —
540 оценок дизайна, не функциональные проверки. Для impeccable использована
явно записанная замена недоступных reviewer/documenter нативными агентами.
Пользовательское одобрение не получено. Дополнительные языки не перечислены;
реализованы RU/EN. Экранный диктор, системная мобильная клавиатура и испытания
с людьми разных возрастов не проведены.

## Как продолжить

Проверьте [приёмку Mintlify](design/mintlify-acceptance.md) и Checks черновика PR3.
Итоговый локальный запуск дал 32 теста, 39 проб правил и 63/63 браузерные проверки.
Снимки покрывают все 11 разделов; узкая настольная таблица дополнительно проверена
по обе стороны границ 1100 и 1280 px. Дальше требуется визуальная приёмка владельцем;
не сливайте PR3 до её получения. Старые PASS не переносите на изменённые исходники.

Сначала проверьте `git status` и согласуйте владение файлами с действующими
исполнителями. Не откатывайте чужую работу; npm устанавливает один участник.
Выберите Issue или создайте его после поиска дубликата. Запишите цель,
область, решения и наблюдаемые критерии. Финансовые примеры фиксированы;
аналитика использует самостоятельные вымышленные наборы, не расчёт трёх покупок.
Наблюдение и оповещения меняют локальные списки. Формы, списки и настройки
живут в памяти вкладки. Настоящие данные и секреты запрещены.

Используйте Node из [.nvmrc](../.nvmrc) и Gitleaks из README:

```sh
npm ci
npm run check
npm run build
npm run preview -- --port 4173
```

При запущенном preview отдельно выполните:

```sh
MULTITRACKER_UI_URL=http://127.0.0.1:4173 npm run test:ui
```

Для исторического кандидата на macOS проверен режим с окном:
`AGENT_BROWSER_HEADED=true MULTITRACKER_UI_URL=http://127.0.0.1:4173 npm run test:ui`.
Команда требует agent-browser 0.38.1 и создаёт свою сессию. Полная матрица
R01–R21, D01–D07, карта каталога, 135 ID и четыре направления арены
шире автоматической цепочки.

Для ручного просмотра интерфейса используйте agent-browser. До первой команды:

```sh
export AGENT_BROWSER_SESSION="$(agent-browser session id --scope worktree --prefix "task-$(date +%s)-$$")"
agent-browser skills get core
```

Проверьте 375/1440 px, RU/EN, действия, ошибки, отмену, повторное сохранение,
переходы, клавиатуру и фокус. Дополнительные границы — в плане доступности.
Сохраняйте ожидание и наблюдаемое следствие через DOM/snapshot, фокус, адрес
или снимок. Неизвестный результат не означает PASS; недоступный инструмент
блокирует зависимую проверку, а не все независимые области.

## Навык и публикация

Комплексный аудит по явному запросу использует
[product-readiness](../skills/product-readiness/SKILL.md).
[Оценка и один фактический вызов Claude Code](reviews/prototype-readiness.md#навык-product-readiness)
не равны полному аудиту MultiTracker в этой среде. Все условные навыки
автоматически не загружаются; диагностика Superpowers требует инцидента.

[check.yml](../.github/workflows/check.yml) задаёт удалённые проверки,
[pages.yml](../.github/workflows/pages.yml) — ручную публикацию статической сборки.
[GitHub Actions №36713961789](https://github.com/apolenkov/multitracker/actions/runs/36713961789)
завершился SUCCESS на публичном корневом коммите: 27 тестов, 39 примеров правил, UI 34/34.
Это исторический запуск семи разделов, не проверка расширения Delta.
Историческая проверка API подтвердила защиту `main`; подробности и границы —
в публичном отчёте. Текущее состояние требует отдельной проверки при изменении.
Размещение приложения не проводилось.
Частные сообщения об уязвимостях включены; порядок — в [SECURITY.md](../SECURITY.md).

## Завершение

Проверьте каждый критерий, запишите точные результаты и ограничения в Issue
и обновите публичный отчёт при изменении его утверждений. Закройте только
собственные браузерные сессии и временные серверы; сохраните доказательства.
Незапущенные проверки не прошли. Перед настоящей реализацией получите одобрение
полного макета и проверьте зависимости соответствующего этапа.
