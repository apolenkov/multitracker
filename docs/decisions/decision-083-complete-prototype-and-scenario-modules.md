# decision-083 — Полный статический интерфейс и модули по сценариям

Статус: accepted. Дата: 2026-09-30. Backlog Decision: decision-083.
Уточняет пункт 3 [decision-078](decision-078-quality-gates-and-module-boundaries.md).

## Контекст

Пользователь хочет проверить всё приложение до реальной реализации. Первый
макет показывал семь разделов, но только часть обязательных форм. Зелёные
проверки узкой спецификации не доказали полноту исходного замысла. Аудит также
обнаружил несколько владельцев черновика импорта и обходы строгих правил типов.

## Решение

1. Принимать макет по [R01–R21](../../openspec/changes/complete-prototype/specs/readiness/spec.md),
   исходному запросу и наблюдаемым последствиям действий. Сначала пользователь
   проверяет полный статический интерфейс, затем начинается настоящий продукт.
2. Группировать модули по уже существующим сценариям: `src/forms/`, `src/records/`,
   `src/insights/`, `src/demo/`; чистая учебная арифметика остаётся в `src/model/`.
   Не создавать пустые `privacy/`, `import/`, `server/` и интерфейсы с единственной
   заглушкой. Будущая криптография и разбор файлов создадут собственные границы
   при реализации и проверке модели угроз.
3. У черновика формы один владелец. Отмена отбрасывает только черновик;
   сохранённые настройки представления живут до перезагрузки вкладки.
   Демонстрационные операции не изменяют проверенные финансовые фикстуры.
4. Использовать установленные типовые правила ESLint и отрицательные проверки
   для небезопасных утверждений, потерянных Promise, TS-подавлений и мутаций Reflect.
   Не обходить ограничения отключениями или упаковкой функций в длинные строки.
5. CI проверяет исходники и ключевые браузерные регрессии на GitHub-hosted runner.
   Публикация статической сборки — отдельное ручное действие. Локальный runner
   другого репозитория остаётся у владельца; его нельзя незаметно переназначить.
6. Аудит использует три независимые UI-линзы, одну консолидацию и одно финальное
   состязательное ревью. Переносимый `product-readiness` маршрутизирует только
   применимые навыки и отделяет доказанный результат от непроверенного.

## Последствия

Код остаётся небольшим React-приложением, без серверной инфраструктуры и новых
зависимостей для форм/маршрутов. Полнота интерфейса проверяется отдельно от готовности
к реальным данным. Не требуется повторное разрешение на уже порученные исправления.
Текущие проверки не доказывают удобство для всех возрастов, работу настоящего
экранного диктора, криптографическую защиту или выполненный запуск GitHub Actions.
