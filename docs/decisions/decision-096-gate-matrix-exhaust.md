# decision-096 — строгая матрица и перебор входят в гейт «check»

Статус: accepted. Дата: 2026-10-03.

## Контекст

Цель [finish-prototype-stage](../../goals/finish-prototype-stage/goal.md) требует,
чтобы строгая матрица 135×8 и запечатанные реестры DOM и функций проверялись
не разовым локальным прогоном, а каждым запуском гейта. Корпус непокрытого
в переборе зависел от порядка обхода, поэтому точное равенство с книгой падало
на исправном дереве.

## Решение

1. После `npm run check` и UI-проверок задание `check`
   ([check.yml](../../.github/workflows/check.yml)) выполняет строгую матрицу
   135×8 и перебор покрытия с реестрами; журналы, отчёты и покрытие сохраняются
   артефактами `upload-artifact`. Каждая запись журнала несёт хеш состояния,
   а DOM каждого уникального состояния лежит в `states.jsonl` рядом с журналом.
2. Перебор детерминирован. Главная причина прежнего разброса и зависаний:
   после клика, сменившего раздел, обход возвращался через `history.back()`.
   Шаг назад асинхронен, при частых переходах возвраты накладывались и уводили
   вкладку на предыдущий документ, а вместе со страницей пропадало задание
   обхода. Теперь возврат идёт явным адресом (`location.hash`). Кроме того,
   перед перечислением состояние приводится в покой, отложенные элементы
   добираются повторно, помеха цели блуждания закрывается перед повтором.
3. Храповик реестров ([ledger.ts](../../scripts/exhaust/ledger.ts)) допускает
   только сжатие: новая непокрытая сигнатура (`missing`) роняет прогон,
   исчезнувшая (`stale`) — законный результат и материал для пересборки книг
   через `npm run exhaust:baseline`.
4. Лимит задания — 90 минут: с полными бюджетами перебор не укладывался в 35.

## Последствия

- Гейт длится заметно дольше; раннер один, прогоны идут по очереди.
  Тяжёлые локальные прогоны параллельно с гейтом не запускаются.
- Обход слоёв 1–3 и блуждания идут в среде `sweepEnv` с `prefers-reduced-motion`:
  анимации раскрытий иначе делали набор видимых элементов зависимым от загрузки
  машины (два параллельных прогона расходились). Анимации в приложении только
  CSS, JS-ветки не меняются; матрица и оси части (b) проверяют движение отдельно.
- Шаг блуждания доходит до цели, как человек: убирает помеху-диалог, переходит
  в раздел цели и раскрывает свёрнутое над ней; только потом пишет пропуск.
- Книги после пересборки 2026-10-03: DOM 473, функции 65. Два прогона подряд
  дали совпадающие корпуса; перебор целиком занимает около 100 секунд.
  Прежние запечатывания (579/69, затем 508/78) получены из обхода, который
  выбрасывало из разделов; владелец принял пересборку.
- Храповик «только сжатие» мягче точного равенства: сокращение книги не роняет
  прогон, поэтому книги пересобираются явно и видны в кодовом ревью.
