# decision-096 — строгая матрица и перебор входят в гейт «check»

Статус: accepted. Дата: 2026-10-03.

## Контекст

Цель [finish-prototype-stage](../../goals/finish-prototype-stage/goal.md) требует,
чтобы строгая матрица 135×8 и запечатанные реестры DOM и функций проверялись
не разовым локальным прогоном, а каждым запуском гейта. Корпус непокрытого
в переборе зависел от порядка обхода, поэтому точное равенство с книгой падало
на исправном дереве.

## Решение

1. После `npm run check` и UI-проверок задание `check`
   ([check.yml](../../.github/workflows/check.yml)) выполняет строгую матрицу
   135×8 и перебор покрытия с реестрами; журналы, отчёты и покрытие сохраняются
   артефактами `upload-artifact`.
2. Перебор детерминирован: перед перечислением состояние приводится в покой,
   бюджеты обхода покрывают очередь раздела целиком, отложенные элементы
   добираются повторно, помеха цели блуждания закрывается перед повтором.
3. Храповик реестров ([ledger.ts](../../scripts/exhaust/ledger.ts)) допускает
   только сжатие: новая непокрытая сигнатура (`missing`) роняет прогон,
   исчезнувшая (`stale`) — законный результат и материал для пересборки книг
   через `npm run exhaust:baseline`.
4. Лимит задания — 90 минут: с полными бюджетами перебор не укладывался в 35.

## Последствия

- Гейт длится заметно дольше; раннер один, прогоны идут по очереди.
  Тяжёлые локальные прогоны параллельно с гейтом не запускаются.
- Книги после пересборки 2026-10-03: DOM 508, функции 78 (прежнее запечатывание
  579/69 получено из недетерминированного обхода).
- Храповик «только сжатие» мягче точного равенства: сокращение книги не роняет
  прогон, поэтому книги пересобираются явно и видны в кодовом ревью.
