# Инвентаризация экранов и форм

Дата: 30 сентября 2026 года. Источник — текущие компоненты `src/`; перечень предназначен для четырёх одинаковых проходов арены дизайна. ID `FORM-001` и далее — устойчивые идентификаторы этого перечня, **не DOM-id**. Новые записи следует добавлять в конец, существующие не перенумеровывать.

Включены маршруты, формы, подтверждения, существенные варианты состава полей/данных, фильтры и раскрываемые панели. Простой текст, декоративные элементы и отдельные строки одинаковых списков не образуют новую форму. Каждый из десяти типов операции выделен отдельно; денежный перевод выделен дополнительно. Пять источников подключения перечислены отдельно, но общий состав их формы не умножается на темы.

Общий обязательный контекст для каждой применимой записи: RU/EN × 375/1440 px × светлое/тёмное оформление; системная тема, монохромность, RUB/USD и скрытие финансовых величин — дополнительные состояния по назначению. Для каждого диалога: вход, X/Cancel/Escape, клавиатура, возврат фокуса; для сохранения — ошибка/успех и повторное действие. Настоящие API, файлы, ключи, торговля, уведомления и шифрование не подключены.

**Граница доказательств.** Этот документ составлен чтением исходников; нового браузерного прохода здесь нет. В последнем столбце указан существующий локальный захват из `docs/audits/2026-09-30-design-arena/raw` либо его отсутствие. «Семейство» означает общий вход, а не доказательство каждого подварианта. Существование PNG/DOM/snapshot проверено; визуальное качество, результат действия и соответствие захвата текущему хешу здесь **NOT VERIFIED**. Эти локальные материалы исключены из публичного Git; публичные выводы линз сохраняются в `docs/design/arena/`. Исторические проверки сентября не заменяют новую оценку арены. Общие опубликованные результаты предыдущих редакций: [обзор готовности](../reviews/prototype-readiness.md) и [редакция дизайна](../reviews/design-revision.md); их область и дата ограничивают применимость.

## Контроль полноты и использование

В перечне **135 записей**. Четыре линзы используют один ID на запись и дают `keep`, `change` или `not observed` с причиной. Переходы/общие поля не создают дополнительные ID: их состояния перечислены в строке. Снимок родительского маршрута не означает, что вложенная форма проверена.

Проверены все места `<form>`, `<dialog>` и `DemoModal` в текущем `src`: `forms/OperationForm`, `forms/EntityDialog`, `records/RecordDialog`, `insights/AssetDetails`, `insights/ManualValuation`, `insights/Report`, `Dialog`, `demo/import-wizard`, `demo/import-history`, `demo/connection-sync`, `demo/connection-form.tsx`, `demo/sync-conflict`, `demo/sync-panel`, `demo/settings-panel`, `demo/settings-dialogs`, `demo/settings-display`, `demo/settings-privacy`, `demo/settings-data`, `market/AssetDialog`, `market/AlertDialog`, `events/EventDialog`, `events/Feed`. Общий `demo/modal.tsx` — оболочка перечисленных диалогов; `Dialog.tsx` также предоставляет общий заголовок и действия.

Содержимое операций определяется `forms/operations.ts` и `forms/OperationFields.tsx`, сущностей — `forms/EntityDialog.tsx`, пяти подключений — `demo/connection-text.ts`, мастера — `demo/import-model.ts` и `demo/import-fields.tsx`, календаря/ленты — `events/data.ts`, рыночных классов — `market/data.ts`. Эти источники прочитаны для определения вариантов, без утверждения о выполнении поведения.

Остальные компоненты подключают или наполняют перечисленные поверхности: `App`, `Workspace`, `DemoScreens`, `ExplorationScreens`, `Forms`, `Records`, `OverviewSummary`, `Holdings`, `OverviewExample`, `Icon`, `analytics/MetricsView`, `analytics/PerformanceTable`, `analytics/SamplePlot`, `market/PriceHistory`, `market/TradingSession`. Отдельных неучтённых форм в них нет; цена/сессия входят в строки рыночных деталей, таблицы/объяснения входят в соответствующие аналитические и финансовые строки.

Два существенных отличия состояния: сохранение сущностей/операций только показывает результат, тогда как избранное, ценовые уведомления и настройки действительно меняются в памяти вкладки; при смене маршрутов панели `DemoScreens`/`ExplorationScreens` остаются смонтированными. Это свойства исходника, а не наблюдение данного прохода. При переключении внутренних разделов аналитики вложенная панель может пересоздаваться — не обещать сохранение всех её локальных выборов.
