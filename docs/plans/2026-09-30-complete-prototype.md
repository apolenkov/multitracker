# Полный макет и готовность MultiTracker

> Для исполнителей: используйте superpowers:subagent-driven-development. Владение
> файлами ниже обязательно; чужие изменения не откатывать. Один общий финальный обзор.

**Цель:** довести основу открытого проекта и полный статический интерфейс до проверки
пользователем до начала настоящего финансового движка и хранения.

**Архитектура:** семь существующих разделов, небольшие React-модули по сценариям.
Данные вымышленные и фиксированные; черновики форм и настройки живут в памяти вкладки.
Сохранение формы закрывает её и сообщает о демонстрации; расчётные примеры не меняются.
Один владелец черновика импорта; общие оболочка, диалог, форматирование и токены.

**Стек:** установленные React, TypeScript, Vite, ESLint, Node test, agent-browser.
**Спецификация:** [OpenSpec](../../openspec/changes/complete-prototype/specs/readiness/spec.md).
**Основание:** исходный запрос, подтверждение «Довести основу и полный макет»,
[публичное резюме аудита](../reviews/prototype-readiness.md).

## Общие ограничения

- Файл ≤300 строк, функция ≤50, обе сложности ≤10; строки JSX и пустые считаются.
- Нет let, изменения объектов на месте, отключений правил, небезопасных утверждений типов.
- RU/EN, RUB/USD; 375/1440 px; зона нажатия ≥44 px, фокус и клавиатура.
- Только вымышленные данные. Нет загрузки настоящего файла, поля секрета, сетевых интеграций,
  хранения, шифрования, серверных заготовок, внешних шрифтов и аналитики.
- Не копировать все возможности конкурентов: торговля, социальная лента, платные тарифы,
  автоматические налоги и инвестиционные рекомендации за пределами этого приложения.
- Проверки и наблюдения сохранять. Неизвестный результат не считать успешным.
- Удалённый репозиторий разрешён явным выбором пользователя 2026-09-30;
  runner другого проекта не переиспользовать. Одобрение полного макета остаётся отдельным.

## Риски, проверяемые в задачах

1. Отмена и Escape должны отбрасывать черновик, а не применять его.
2. Язык и переход между разделами не сбрасывают выбранные настройки/сопоставление.
3. Второе сохранение тоже объявляет результат; «Назад» остаётся внутри навигации приложения.
4. Пустые, отрицательные, ошибочные суммы/даты и неполное сопоставление не дают успех.
5. Скрытые суммы не раскрываются в подробностях/отчёте; мобильный подвал не закрывает действия.

## Уточнения трёх независимых проверок плана

- Показать минимум два счёта внутри одного портфеля, фильтр счёта и его выбор в операции, импорте и подключении.
- Поля операции включают валюты цены/комиссии, источник/назначение; перевод между одним и тем же счётом запрещён. Контекст актива/счёта передаётся в открываемую форму.
- Журнал содержит отдельные фиксированные примеры непокупочных операций, явно не участвующие в расчётной сцене.
- Импорт объясняет причину ошибки, позволяет решить повтор и показывает количества добавляемых/пропущенных/ошибочных строк. Обязательные поля зависят от формата.
- Новые ошибки связаны с полями через aria-describedby/aria-invalid, фокус получает первая ошибка. Скрытые поля не проверяются.
- Все диалоги удерживают Tab/ShiftTab, закрываются Escape, возвращают фокус или используют существующий запасной получатель. При уходе со страницы открытый диалог закрывается.
- Ссылки навигации имеют href; закрытие вложенного сценария сохраняет портфель и фильтры. Скрытые страницы исключены из доступного дерева.
- Дополнительно проверить 375×500, 320 CSS px и настоящий browser zoom200. Малая высота не считается испытанием экранной клавиатуры, CSS zoom не считается browser zoom.
- Основные действия видны сразу; редкие сгруппированы в подписанных блоках.
