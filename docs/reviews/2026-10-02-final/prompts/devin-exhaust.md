### Layer 2 — element coverage

### Invariants checked after EVERY click (fail with the repro record)
no console error/warning from the app; no horizontal overflow (scrollWidth <= viewport); no unexpected layout shift outside the clicked element's own container (use the project's shift measurement; sticky/fixed containers excluded the legitimate way already used in scripts/ui-smoke*); focus is visible and inside the viewport after dialog open/close/undo; with hide-amounts ON no digit-with-currency pattern, no ▲/▼ and no positive/negative classes appear in the DOM text/classes of masked values; every interactive element has an accessible name; targets >= 44 px (inline-text-link exception documented); no duplicate ids; at most one dialog open; RU/EN: no untranslated key or missing string.


### Layer 4 — design review AT CLICK TIME (owner requirement: "when you click, review immediately, for design too")
Every click that produces a NEW state (state-hash not seen before; dedupe by hash) is reviewed on the spot, inside the same run, not afterwards:
1. Deterministic design checks computed from the live DOM/CSS right after the click settles (all against DESIGN.md and src/appearance.css tokens — read them, do not hard-code a second copy; derive the token table by parsing the CSS custom properties at run time):
   - font sizes only from the documented scale; font weights from the documented set; line-height sane;
   - colours only from tokens (text/background pairs must come from the token set), contrast ratio >= 4.5:1 for text (3:1 large text and UI components), computed over the real rendered background (walk up to the first opaque ancestor), in BOTH themes and monochrome;
   - spacing/padding/gap values from the documented scale (8/12/16/20/24/28/32) with a small tolerance list; radius from {8, 12, 6, 4, 2, 50%};
   - text clipping/truncation: scrollWidth > clientWidth or ellipsis without a title/accessible full text; text overlapping other text/controls (bounding-box intersection of text rects and interactive rects that are not parent/child); elements outside the viewport horizontally; sticky header/footer covering a focused element;
   - alignment: siblings in a row share baseline/centre within 2 px; list rows have equal height within a group; icons/buttons in a row aligned; no orphan single word on its own line in headings (text-wrap balance check), no single-character line breaks;
   - interactive affordance: every clickable element has a visible focus style and a non-default cursor; disabled elements are visibly distinct; selected/pressed states are visibly distinct from unselected (computed-style difference);
   - hierarchy sanity: exactly one h1 per route, heading levels not skipped, one primary action per dialog;
   - motion: respects prefers-reduced-motion (run a sample with it on).
   Each failure is a finding attached to the click record (`design: [{rule, selector, expected, actual}]`) and counted in the report; severity by rule.
2. Screenshot of each new state (viewport + full page when it scrolls), saved with the state hash as file name, plus an annotated copy with failing elements boxed in red. Cap storage: png <= 400 KB each via resolution scaling for non-failing frames; keep full-size only for failures.
3. AI visual review, streamed: a background worker batches the distinct new-state screenshots (50 per batch, contact sheets with captions = click record id) and sends each batch to a reviewer run (headless `devin -p` read-only, one prompt per skill lens: frontend-design, web-design-guidelines, ui-ux-pro-max — three parallel runs per batch, results consolidated by click record id into `visual-findings.jsonl`). Do NOT use Claude subagents. The explorer does not wait for the AI reviews to continue clicking, but the final report joins them (finding -> click id -> screenshot) and the run exits non-zero if any Critical/Important visual finding is unresolved. Provide `--no-ai-review` for fast local runs; the deterministic Layer-4.1 checks always run.
4. Report section "Design review at click time": counts by rule, top offenders by selector, per-route heat table (clicks, new states, findings), and the list of screenshots with findings.
