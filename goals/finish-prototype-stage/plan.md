# План: закрытие этапа макета

Основание: [facts.md](facts.md) — 12 принятых фактов (10 с автопроверкой), ответы
интервью ([interview-result.json](interview-result.json)). Гейт — self-hosted раннер
OrbStack ([decision-095](../../docs/decisions/decision-095-self-hosted-container-runner.md)).

## Подход

Опираемся на существующий перебор `scripts/exhaust/*` (оси, реестр элементов,
покрытие кода, запечатанный храповик) и добавляем два недостающих слоя:
машиночитаемый инвентарь 135 ID и строгую матрицу 135×8. Локальные прогоны и гейт
идут в одном CI-образе. Правила не ослабляем; артефакты сохраняем; длительности
замеряем. Порядок: сначала инфраструктура, затем матрица и реестры, затем гейт,
документы, публикация и гигиена.

## Шаги

1. **Node 26 и типы** (fact-deps). `.nvmrc` → 26.10.0, `engines` → `>=26.10.0`,
   README (закреплённая версия), `scripts/runner/Dockerfile` (база Node 26);
   принять dependabot PR #1 (`@types/node` 26.6.3). Проверка: `node -v`;
   `npm run check` на Node 26 (уже observed: exit 0, 83 теста); CI; в контейнере
   `node -v` = 26.x.
2. **Общий CI-образ и `test:ui:docker`** (fact-docker). В образ добавить Node из
   `.nvmrc`, `agent-browser@0.38.1` и `gitleaks` 8.30.1; `scripts/ui-docker.sh`,
   `scripts/exhaust-docker.sh`, `package.json` переводят на этот образ; убрать
   ссылки на `multitracker-layout-runtime:20260930` (README, decision-092 — с
   пометкой истории). Проверка: сборка образа с нуля; `npm run test:ui:docker` —
   exit 0, 53/53; grep по имени старого образа пуст.
3. **Инвентарь 135 ID** (fact-matrix). `scripts/exhaust/inventory.ts` + данные,
   тест `tests/exhaust-inventory.test.ts`: разбор таблицы
   `docs/design/form-inventory.md`, уникальные ID, вход и применимые контексты
   у применимых записей, «вне текущего объёма» — с причиной, счёт 135 сохранён.
   Проверка: `npm test`.
4. **Строгая матрица 135×8** (fact-matrix, fact-evidence). `scripts/exhaust/matrix.ts`
   и шаги входов (модули ≤300 строк), новый слой в `scripts/exhaust/run.ts`;
   для каждого ID × RU/EN × 375/1440 × светлая/тёмная: открыть состояние,
   проверить роли/имена, границы/обрезку, hit-test, фокус, ошибку/исправление,
   сохранение/отмену/повтор по применимости; PASS/N-A с причиной; журнал JSONL
   и отчёт. Проверка: контейнерный прогон — 1080 ячеек, 0 FAIL/NOT VERIFIED;
   отчёт и длительность сохранены.
5. **Скорость** (fact-speed). Замер базовой длительности; ожидание условий вместо
   пауз (единственный `setTimeout`-settle в `page-dom.ts` оставить как rAF-settle);
   переиспользование сессии браузера; при необходимости — две параллельные сессии.
   Проверка: замер до/после записан в отчёт; прогон зелёный; grep задержек чист.
6. **Реестры на текущем main** (fact-ledgers). Полный прогон → `npm run exhaust:baseline`
   (только вручную) → заново запечатанные `uncovered-ledger.json` (DOM) и
   `uncovered-code-ledger.json` (функции); новые непокрытые — исправить или
   исключить с причиной. Проверка: `npm test` (храповик), `git diff` книг —
   только сокращение или пересборка с объяснением.
7. **Гейт целиком** (fact-gate). `.github/workflows/check.yml`: после `npm run check`
   — UI, смоук, матрица и перебор на раннере; артефакты (журналы, отчёты,
   покрытие) — `upload-artifact`; длительность зафиксировать. Проверка: push →
   зелёный прогон на `mt-orbstack`, артефакты скачиваются.
8. **Счётчики единообразно** (fact-counters). Один приём числа (бейдж-счётчик) и
   склоняемый текст во всех местах: `src/records/*`, `src/Overview*.tsx`,
   `src/Holdings*.tsx`, `src/*.css` (токен), `DESIGN.md`; проверка в
   `scripts/check-ui.ts`. Проверка: `npm run check`; UI-проверка общего класса
   счётчиков; скриншоты 375/1440.
9. **Рамка фокуса — запись** (fact-focus). В `docs/reviews/2026-10-02-ui-ux-lane.md`
   зафиксировать: поведение задумано (DESIGN.md, фокус вокруг заголовка),
   изменение кода не требуется.
10. **Публикация на Pages** (fact-pages). Включить Pages (`build_type=workflow`)
    через `gh api`, запустить `pages.yml`, дождаться деплоя, проверить URL
    браузером (заголовок, «Обзор», консоль), добавить ссылку в README и приёмку.
    Проверка: HTTP 200, браузерная проверка, ссылка в README.
11. **Приёмка и отчёты** (fact-acceptance). `docs/design/product-ui-acceptance.md`
    (PENDING-строки закрыть результатами матрицы и гейта), архивировать
    `layout-smoke-polish` (без переноса устаревшей спеки), обновить README,
    `AGENTS.md`, `docs/agent-handoff.md`. Проверка: `openspec validate --all --strict`;
    grep PENDING и старых утверждений пуст.
12. **Гигиена** (fact-hygiene). Убрать воркдри `multitracker-pr3`, смерженные
    ветки и шимы (`/tmp/ab-shim`, `/tmp/ab-pin`, `/tmp/mt-verify*`), остановить
    dev-серверы; локальные доказательства оставить. Проверка: `git status`,
    `git worktree list`, `git branch -a`.

## Риски

- Матрица 1080 и перебор в гейте удлиняют прогон; шаг 5 обязан дать замер и
  максимум ускорения без потери доказательств. Если бюджет окажется неприемлемым —
  отдельное решение владельца, без ослабления покрытия.
- Node 26: локальный `npm run check` зелёный; остаётся проверить контейнер и CI.
- Инвентарь: 45+ ID «вне текущего объёма» — исключаются с причиной, нумерация
  не переиспользуется.
- Реестры: прогон может показать новые непокрытые элементы/функции — их нужно
  покрыть или объяснить; храповик не ослабляем.
- Pages: включение Pages в настройках репозитория; при недоступности — записать
  границу честно.
- Один раннер: прогоны PR идут по очереди; длинный гейт увеличивает ожидание.
