# Исполнение утверждённого плана

## Baseline и наблюдаемое действие

До изменений приложения задача 1 работает только в тестах. На `1e64f81`
F1 (`min-content 1fr`) и прежний вертикальный скачок F2 (`align-items: start`)
должны дать GREEN; меню в потоке/эксклюзивность проверяются отдельно.
Чувствительность проверяют временным CSS прежней ошибки: отдельный результат
RED, затем гарантированное удаление CSS даже при сбое. Эти результаты не
означают регрессию текущей сборки. F4 проверяет новое требование исходной
видимости, отдельно от ранее доказанной достижимости прокруткой.

`details > summary` собирают из DOM и открывают настоящим click/Enter;
присваивание open не заменяет действие. Сдвиг summary, элементов выше и
соседей той же строки ограничен 2 CSS px. `rows[].centerYDelta` помогает
разобрать геометрию, но сам по себе не делает смешанную строку ошибкой.
Видимость основного действия измеряют до inspectDom: hit-test может
прокрутить страницу. Закрепление подвала после прокрутки проверяют отдельно.
Именованные agent-browser-сессии изолируют исполнителей. Неизвестное следствие
не получает PASS; журнал связывает найденную цель, действие и результат.

## Оформление и совместимость

Нативные details сохраняют действия без поддержки анимации. Движение —
постепенное улучшение: явные transition-свойства, reduced motion, мгновенное
раскрытие без новых браузерных возможностей. Меню операций и счетов имеют
раздельные группы; Escape закрывает меню и возвращает фокус. Диалоги сохраняют
ограничение Tab и возврат фокуса. Цели управления — не меньше 44 CSS px.

Цвет берут из действующих токенов и существующих символов активов; неизвестный
символ нейтрален. Типографика суммы использует Intl.NumberFormat.formatToParts
с сохранением валют, скрытия и локали. Легенда имеет четыре колонки только
при достаточной ширине, иначе перенос без обрезки. Линия использует имеющийся
ряд, без добавления финансовых данных. Все десять операций должны показывать
основное действие сразу; единое оформление полей не имитирует отключение.

## Приёмка

Smoke дополняет, а не заменяет строгую инвентаризацию 135 ID. После последней
правки приложения весь обязательный набор снимают заново: каждый из 135 ID
во всех применимых RU/EN × 375/1440 × light/dark, восемь сочетаний с предметным
обоснованием каждого N/A. Прежние 540 состояний оказались неполной матрицей;
исторические отчёты не переписывают. Новые результаты сверяют с исходниками;
старые результаты не переносят. npm check, UI (сохранённые 68 сценариев), Google
DESIGN и строгий OpenSpec проходят без ослабления правил. Один независимый
итоговый обзор получает полный пакет и включает проверку исправлений находок.
Визуальное одобрение владельца ожидается отдельно; инженерный PASS его не заменяет.
